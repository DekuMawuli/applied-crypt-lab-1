# Design v1 – LFSR + Permutation File Cipher

Implements requirements_v2.md. Python 3, tkinter, standard library only.

## 1. Approach in one paragraph
Process the file in chunks. For each byte: permute the bits (encrypt) and XOR with the next LFSR byte, or XOR first and inverse-permute (decrypt). The permutation is precomputed as two 256-entry lookup tables, so it costs one list lookup per byte. The key stream is generated by a small LFSR class that keeps its state between chunks, so the stream is continuous across the file. Work runs in a thread and reports progress to the UI.

## 3. LFSR (cipher.py)
State is a 19-bit integer `reg`. Bit 0 is the leftmost cell and the LSB (the x^1 cell); bit 18 is the rightmost cell (the x^19 cell).

- **Init:** `reg = 0x67BD5`. The seed's LSB lands in bit 0 and its MSB in bit 18 (conventions 13c).
- **Output bit:** `out = (reg >> 18) & 1`, the rightmost cell, which is the seed's MSB on the first step (13d).
- **Feedback bit:** XOR of the cells for x^14, x^17, x^18, x^19, i.e. bits 13, 16, 17, 18: `fb = ((reg >> 13) ^ (reg >> 16) ^ (reg >> 17) ^ (reg >> 18)) & 1`. The "1" term of the polynomial is the feedback connection itself.
- **Shift:** `reg = ((reg << 1) & 0x7FFFF) | fb`. Everything moves right (toward higher bits) and the feedback enters on the left at bit 0 (13b).
- **Byte assembly:** eight steps; the first output bit is bit 0 of the byte, the second is bit 1, and so on (13e):
```
def next_byte(self):
    b = 0
    for i in range(8):
        out = (self.reg >> 18) & 1
        fb = ((self.reg >> 13) ^ (self.reg >> 16) ^ (self.reg >> 17) ^ self.reg >> 18) & 1
        self.reg = ((self.reg << 1) & 0x7FFFF) | fb
        b |= out << i
    return b
```
Since the key stream does not depend on the data, a chunk of key stream is produced with `bytes(lfsr.next_byte() for _ in range(n))` and applied with one XOR pass.

## 4. Permutation
Indices are 1..8 with index 1 the MSB, so index i corresponds to bit position `8 - i` (bit 7 is index 1, bit 0 is index 8). With `PI = {1:2, 2:6, 3:3, 4:5, 5:1, 6:8, 7:4, 8:7}`, `permute_byte` below implements reading A (input bit at index i moves to index PI[i]). **Reading B is the one in use** (output bit i takes input bit PI[i], i.e. the same function applied with the inverted mapping), because only B decrypts the instructor's image:
```
def permute_byte(b):
    out = 0
    for i, j in PI.items():
        if (b >> (8 - i)) & 1:
            out |= 1 << (8 - j)
    return out
```
Build `PERM = [permute_byte(b) for b in range(256)]` and `INV = [0]*256; INV[PERM[b]] = b`. A flag `PERMUTATION_READING` (now `"B"`) swaps to reading B by inverting the mapping (`PI` replaced by its inverse), so the decision in requirements "Open decisions" is a one-line change.

## 5. File processing
```
def process(in_path, out_path, mode, progress=None, chunk=65536):
    lfsr = LFSR(KEY)
    total = os.path.getsize(in_path)
    done = 0
    with open(in_path, 'rb') as f, open(out_path, 'wb') as g:
        while data := f.read(chunk):
            ks = lfsr.stream(len(data))
            if mode == 'encrypt':
                out = bytes(PERM[d] ^ k for d, k in zip(data, ks))
            else:
                out = bytes(INV[d ^ k] for d, k in zip(data, ks))
            g.write(out)
            done += len(data)
            if progress: progress(done, total)
```
- The LFSR is created once per file, so the key stream is continuous across chunks.
- Output is written to the same length as the input; no header or padding.
- A few-megabyte image takes on the order of seconds in pure Python (the 8-step byte generator dominates); acceptable for the lab. If it proves slow, the key stream can be precomputed once per period or generated with a lookup of 8-step transitions.
- The output is written to a temporary name in the target folder and renamed on success, so a failed run does not leave a half-written file in place of an existing one.

## 6. UI (ui.py)
```
+----------------------------------------------+

| Input file:  [______________________] [Browse]|
| Output file: [______________________] [Browse]|

```
- `ttk.Radiobutton` for the mode, `ttk.Entry` plus Browse buttons (`filedialog.askopenfilename` / `asksaveasfilename`), `ttk.Progressbar` in determinate mode (0-100).
- **Threading:** Start runs `process` in a `threading.Thread`. The worker never touches Tk widgets; it puts `(done, total)` into a `queue.Queue` and the UI polls the queue with `root.after(50, ...)` while a run is active, so the bar updates and the window stays responsive. The final message or error is delivered the same way. Start is disabled during the run and re-enabled at the end.
- **Validation:** checked on Start per requirement 11 (empty or missing input, empty output, output same as input via `os.path.samefile` or normalized path compare, overwrite confirmation via `messagebox.askyesno`). Errors from the worker (permissions, disk full) are shown in `messagebox.showerror` and in the status line.
- When the input is chosen and the output is empty, suggest an output name: `name.enc` for encrypt, and for decrypt the name with a trailing `.enc` removed, or `name.dec` if it does not end in `.enc`.

## 7. Error handling
- Missing or unreadable input, unwritable output → error dialog with the OS message; nothing is left behind (temporary file removed).
- Empty input file → produces an empty output file, progress goes straight to 100%.

## 8. Testing (tests/test_cipher.py, pytest or unittest)
- Permutation: `PERM` is a bijection of 0..255; `INV[PERM[b]] == b` for all b; a single-bit example: under reading B, output index 1 (MSB) takes input index 2, so 0x40 maps to 0x80.
- LFSR: with the seed 0x67BD5 the first output bit is 1 (the seed's MSB: 0x67BD5 = 110 0111 1011 1101 0101 in 19 bits, so the first bits out are 1,1,0,0,1,1,1,...) and the first key-stream byte is computed by hand from the conventions and compared; the register never becomes zero over the first million steps.
- Round trip: random bytes of several lengths (including 0 and sizes straddling the 64 KiB chunk) encrypt then decrypt back to the original, also with a different chunk size to prove chunking does not change the output.
- Interop: decrypt the instructor's encrypted image and check the result starts with a valid image signature (for example PNG `89 50 4E 47` or JPEG `FF D8 FF`) and opens in Pillow if available. This is the check that settles the permutation direction.
- All-zero plaintext: encrypting zeros equals the key stream (permute(0) = 0), which is a quick check of the LFSR output.
- UI is checked manually: modes, browse dialogs, progress bar movement, validation messages, overwrite prompt.

## 10. Risks and decisions
- **Permutation direction (resolved):** reading A produced garbage (`ff 1b ff 38...`); reading B produced a valid JPEG (`ff d8 ff e0 ... ff d9`).
- **Feedback taps and output cell:** derived from the written conventions (13a-d). A mistake here (for example using bit 0 as the output) would give garbage; the interop test catches it.
- **Pure-Python speed:** fine for lab-sized images. A larger file would warrant precomputing the key stream.
- **Security note:** this construction is a toy cipher: an LFSR key stream is vulnerable to a known-plaintext attack (Lecture 2). It is for the exercise only.
